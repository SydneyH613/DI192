Forms & JSON — HTTP, GET, POST, and data serialization

GET

Exercise 1 — HTML Form (GET method)

📍 Where does the data appear?
With method="GET", the form data is appended to the URL as a query string.
After clicking Send, look at your browser's address bar — you'll see something like:
exercises.html?name=Mario&message=Hello+World
The data is visible in the URL, bookmarkable, and logged in browser history.
POST

Exercise 2 — HTML Form (POST method)

📍 Where does the data appear?
With method="POST", the data is sent in the HTTP request body — it does not appear in the URL.
To see it: open DevTools → Network tab → click the request → look at Payload / Form Data.
POST is better for sensitive data (passwords, long text) since it's hidden from the URL bar and browser history.
JSON

Exercise 3 — JSON Mario

const marioGame = { /* the full JS object */ }; const jsonString = JSON.stringify(marioGame); console.log(jsonString);

What happens to nested objects?

  • Nested objects are serialized recursively — they become nested JSON objects { } inside the string.
  • The result is a single flat string. All levels of nesting are preserved but encoded as text.
  • Keys become double-quoted strings (unlike JS where quotes are optional).
  • undefined, functions, and Symbols are omitted during serialization.
// Pass null (replacer) and 2 (spaces) for pretty-print const prettyJson = JSON.stringify(marioGame, null, 2); console.log(prettyJson);

The 3 arguments of JSON.stringify

  • value — the JS object to convert.
  • replacer — null means "include everything". Can be an array of keys to keep, or a function to filter.
  • space — number of spaces (or a string) used for indentation. 2 gives the classic readable format.
// Open DevTools → Sources tab → click this line number to set a breakpoint const marioGame = { detail: "An amazing game!", characters: { /* ... */ } }; const jsonString = JSON.stringify(marioGame); // ← set breakpoint here const prettyJson = JSON.stringify(marioGame, null, 2); // ← or here debugger; // This line also pauses execution automatically

How to use the debugger

  • Open DevTools with F12 or Cmd+Option+I.
  • Go to the Sources tab and find this HTML file.
  • Click a line number to set a breakpoint — execution pauses there.
  • The debugger; statement acts like a programmatic breakpoint.
  • In the Scope panel on the right you can inspect jsonString and prettyJson live.
